Chat Orchestration

Lets a user describe what they want and have SimpleChat work out the rest. Instead of choosing documents, web search, a prompt, an agent and a model before asking, the user asks; SimpleChat plans the work, shows the plan, and runs it once approved.

Orchestration only reaches capabilities this deployment already allows. Turning it on does not grant a user access to anything they could not already use by hand.

Available in the V2 interface only.
Plan Approval

How much say a user has before a plan runs. Reviewing every plan is the safest default and the slowest; approving automatically is the fastest and gives the user no chance to intervene before work starts.

How long the user has to intervene when the mode is a countdown. Between 3 and 120 seconds.
Capabilities
Off by default. Requires Chat Orchestration and Semantic Kernel. Lets plans use an existing personal, group or global action directly, without loading a configured agent. Existing access and governance still apply. A step can call several functions from its selected action within the run limits; gathering knowledge does not make an action read-only.
Off by default, because an approved proposal becomes a standing personal workflow that keeps running on the user's behalf. Requires Chat Orchestration and Enable Personal Workflows. When a user asks for recurring or automated work, such as a weekly summary, a plan can propose a personal workflow as a card in the user's own private conversation. Nothing is created until the user approves the card, and the workflow limits under Limits apply.
Off by default, because a run does whatever its workflow is set up to do, with the user's access. Requires Chat Orchestration and Enable Personal Workflows. When a user asks for it, such as "run my weekly digest now", a plan can start one of the user's saved personal workflows from the user's own private conversation. A plan that starts a workflow always waits for the user to run it, whatever the approval mode, and approving it starts each named workflow once. Only workflows with durable execution on can be started this way.

Which kinds of work a plan may contain. Leave every box ticked to allow whatever the rest of this deployment's settings already permit; untick one to keep it out of plans even where it is otherwise enabled. An empty selection also means every otherwise-enabled capability. Use an action still requires Enable Action Access.

Plans need Prepare content to write a chat answer or the content of a file, and Create a file to deliver a downloadable file. Generate images also requires Image Generation. Read workflow results also requires Use Workflow Results In Chat and personal workflows.

Limits

Bounds on a single run. These are what stop a badly-shaped question turning into an open-ended amount of work, so they are enforced regardless of what a plan asks for.

How often a step may send the plan back to be reconsidered.
How much of the conversation's earlier work the planner can see, so it reuses findings instead of repeating them. Zero makes every turn plan from scratch.
The most workflows a chat plan may create for one user. Workflows built in the workflow editor do not count.
The shortest repeat interval a chat plan may give a workflow it creates. Daily, weekly and monthly schedules always pass.
Planner Model

Which model writes the plan. Planning is a short, structured task rather than a conversational one, so a smaller and faster model usually does it well and costs less per message than the model that writes the answer.

Lists the models your AI Connections publish for chat, or the classic deployments when connections are off. Keep Use the answer model to plan with whichever model answers.
The saved planner model is not one of the models listed here. It is kept until you choose another; planning fails rather than switching models if it cannot be used.
