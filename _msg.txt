Merge origin/paullizer-react-v2-ui (Agents & Actions) at 0.261.082

Takes #1424's deletion of `actions-config` rather than resurrecting it. Both its
fields moved into `core-plugin-toggles`, and the union check now distinguishes a
field that moved from one that vanished: a section deleted on the base is
dropped, and its fields are only allowed to disappear if the base rehomed them.
Both `enable_text_plugin` and `enable_default_embedding_model_plugin` are
accounted for there.

Registry merged as the verified union: 67 sections, 307 fields, none lost and
none with two writable declarations. `enable_fact_memory_plugin` is declared
twice on purpose -- Chat owns the writable one, and #1424's plugin roster
carries a `readonly` mirror -- so the duplicate check now tests for two
*writable* declarations rather than two declarations.

Three collisions in the shared registry needed merging rather than choosing:

  * `_apply_nested_paths` existed on both sides for two different descriptors.
    Mine folded dotted `paths`, theirs folded segmented `settings_path`. One
    function now does both, running whichever container normalizer applies.
  * `_normalize_string_list` likewise. Theirs bounds the Key Vault reminder
    roles with `max_item_length` and restores the default through
    `fallback_when_empty`; mine validates the URL Access domain lists with
    `entry_pattern` and `max_entries`. Both descriptor sets are declared in the
    merged schema, so both are honoured.
  * `LEGACY_FIELD_NAMES`, `LEGACY_FIELDS_WITHOUT_V2_EQUIVALENT` and
    `V2_ONLY_FIELDS` were each about to be declared twice, which would have let
    the later one silently win. Merged into one declaration apiece.

The TypeScript side had diverged further, into two parallel vocabularies for the
same ideas. Rather than pick, the base's file is the spine and my capabilities
are folded back in: dependencies now evaluate `any_of`, `all_of` and
`not_equals` as well as the base's runtime `flag` conditions, and
`readFieldValue` resolves both nested-path descriptors plus the unit `scale`
that File Sync's per-run limit needs.

`SettingsSection` stays as the section shell because the base's inline panel is
a subset of it -- the status pill it added is what the shell already draws from
its status rule. The one thing the shell lacked was the base's `collapsed`
group, so grouping now carries it and a group declared closed starts closed.

Also restores a guard the merge dropped from the schema test, which read
`field["depends_on"]` on every field and raised for the ones without it.
