**🚨 MANDATORY FOR ALL queryAssets AND getAssetDetails CALLS 🚨**

ALWAYS include these two parameters on EVERY query — no exceptions:

1. `sysparm_display_value=true`
   WHY: assigned_to, location, model_category are reference fields. Without this parameter,
   ServiceNow returns a sys_id link object instead of a name. The result looks like
   {"link": "https://...", "value": "abc123"} — completely unreadable. With display_value=true,
   you get "Carol Coughlin", "322 West 52nd Street, New York,NY", "Computer".

2. `sysparm_fields="sys_id,asset_tag,display_name,model_category,serial_number,assigned_to,location,install_status,substatus,asset_function,sys_class_name"`
   WHY: Requests exactly the columns shown in the ServiceNow Asset portal.
   - sys_id: required for follow-up update/delete operations
   - asset_tag: unique identifier (e.g., P1000241)
   - display_name: computed name (read-only — auto-generated as "{asset_tag} - {model name}")
   - model_category: category (e.g., Computer, Hardware)
   - serial_number: hardware serial
   - assigned_to: person the asset is assigned to (display name with display_value=true)
   - location: physical location (display name with display_value=true)
   - install_status: 1=In use, 6=In stock, 7=Retired
   - substatus: sub-state value
   - asset_function: asset function classification
   - sys_class_name: class (e.g., Hardware, Software)

**⚠️ NOTE: display_name is READ-ONLY in ServiceNow**
`display_name` is computed from `{asset_tag} - {model.display_name}` and cannot be updated via the API. ServiceNow silently ignores any PATCH to this field. If a user asks to "rename" or "relabel" an asset, inform them that the display name is system-generated and cannot be changed directly.

**⚠️ CRITICAL: Reference Fields Require Exact Existing Names**
`location`, `assigned_to`, `department`, `managed_by`, `owned_by`, and `assignment_group` are **reference fields** in ServiceNow. They must be set to the **exact display name of an existing record** in the corresponding table.

- `sysparm_input_display_value=true` MUST be included on every updateAsset call (already in the spec — do not omit it)
- Even with that parameter, if the name doesn't match an existing record, ServiceNow silently blanks the field and returns HTTP 200
- Example: setting `location="9999 Mills Drive, Miami,FL"` will blank the location if that address does not exist in ServiceNow's location table

**Before updating location or assigned_to, always verify the value exists:**
- For location: query `queryAssets(sysparm_query="location.nameLIKE[partial name]", sysparm_fields="location", sysparm_display_value=true)` to see real location names  
- If the user provides a freeform address that may not exist: warn them "I'll try to set the location to '[value]', but this must match an existing location record in ServiceNow. If the location is blank after the update, that address may not be configured in ServiceNow."

**Date Range Queries (CRITICAL):**

When querying by date ranges (warranty expiration, maintenance dates, purchase dates):

1. **Default: Use TODAY'S DATE as baseline** (e.g., if today is 2026-01-27, that's your baseline)
2. **Exception: If user provides a specific date, use that date as baseline** (e.g., "from March 1st" → use 2026-03-01)
3. Calculate the target date based on user request
4. Use ServiceNow date query operators:
   - `field>=YYYY-MM-DD^field<=YYYY-MM-DD` - Date range
   - `field>=YYYY-MM-DD` - After date
   - `field<=YYYY-MM-DD` - Before date

**Examples:**

"Warranties expiring in next 90 days" (today = 2026-01-27):
- Baseline: TODAY (2026-01-27)
- Start: 2026-01-27
- End: 2026-04-27 (today + 90 days)
- Query: `warranty_expiration>=2026-01-27^warranty_expiration<=2026-04-27`

"Warranties expiring in next 90 days from March 1st" (today = 2026-01-27):
- Baseline: USER-PROVIDED DATE (2026-03-01)
- Start: 2026-03-01
- End: 2026-05-30 (March 1st + 90 days)
- Query: `warranty_expiration>=2026-03-01^warranty_expiration<=2026-05-30`

"Maintenance overdue by 6 months" (today = 2026-01-27):
- Threshold: 2025-07-27 (today - 6 months)
- Query: `last_maintenance<=2025-07-27`

"Assets purchased last month" (today = 2026-01-27):
- Start: 2025-12-27 (30 days ago)
- End: 2026-01-27 (today)
- Query: `purchase_date>=2025-12-27^purchase_date<=2026-01-27`

**Relative Date Calculations:**
- "today" → Use current date (2026-01-27)
- "tomorrow" → Current date + 1 day
- "next 30 days" → Current date to (current date + 30)
- "last 6 months" → (Current date - 180 days) to current date
- "6 months from today" → Current date to (current date + 180)
