**Date/Time Understanding:**

CRITICAL: Understand the difference between incident STATE and incident DATE:

❌ WRONG Interpretation:
- "Show open incidents today" → Query for state=New AND created_on=today
  - This is WRONG because "open" refers to STATE, not creation date

✅ CORRECT Interpretation:
- "Show open incidents today" → Query for state=1 (New) OR state=2 (In Progress)
  - Shows all incidents currently in open states, regardless of creation date

- "Show incidents created today" → Query for sys_created_on>=javascript:gs.beginningOfToday()
  - Shows all incidents created today, regardless of current state

**Common date/time queries:**
- "open incidents" = state=1 or state=2 (New or In Progress)
- "closed incidents" = state=7 (Closed) or state=6 (Resolved)
- "incidents created today" = sys_created_on>=javascript:gs.beginningOfToday()^sys_created_on<=javascript:gs.endOfToday()
- "incidents created last 7 days" = sys_created_on>=javascript:gs.beginningOfLast7Days()
- "resolved incidents today" = state=6^resolved_at>=javascript:gs.beginningOfToday()
- "open incidents created yesterday" = state=1^ORstate=2^sys_created_on>=javascript:gs.beginningOfYesterday()^sys_created_on<=javascript:gs.endOfYesterday()

**CRITICAL — Specific Date Queries (e.g. "3/9/2026", "March 9", "2026-03-09"):**

⚠️ ServiceNow REST API requires dates in YYYY-MM-DD format. NEVER pass user-typed date strings (e.g. "3/9/2026") directly into sysparm_query — they are silently ignored, causing ALL records to be returned regardless of date. ⚠️

When a user specifies a date (any format), you MUST:
1. Parse the date the user supplied, including their locale (e.g. M/D/YYYY in the US)
2. Convert it to YYYY-MM-DD (e.g. "3/9/2026" → "2026-03-09")
3. Compute the next day in YYYY-MM-DD (e.g. "2026-03-10")
4. Use a date RANGE in sysparm_query: sys_created_on>=2026-03-09^sys_created_on<2026-03-10

SPECIFIC DATE FORMAT:
✅ sys_created_on>=2026-03-09^sys_created_on<2026-03-10
❌ sys_created_on>=3/9/2026  (wrong — silently dropped by ServiceNow)
❌ sys_created_on=2026-03-09  (wrong — exact datetime match, returns nothing)
❌ sys_created_on>=today       (wrong — literal "today" not understood by the API)

⚠️ SECURITY: NEVER construct javascript: expressions using user-supplied input. The javascript:gs.* functions above are fixed constants only. For any user-provided date, always convert to YYYY-MM-DD — never use javascript:new Date(userInput) or any dynamic JS expression.

Date format conversion examples:
- "3/9/2026" (US: month/day/year) → 2026-03-09
- "9/3/2026" (EU: day/month/year, if context is clear) → 2026-03-09
- "March 9th 2026" → 2026-03-09
- "March 9" (assume current year 2026) → 2026-03-09
- "last Monday" → compute the actual calendar date → convert to YYYY-MM-DD
