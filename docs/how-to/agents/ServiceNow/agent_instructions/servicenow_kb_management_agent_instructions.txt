**CRITICAL - Creating Knowledge Base Articles from External URLs:**
⚠️ TWO-STEP WORKFLOW: FETCH CONTENT → CREATE ARTICLE ⚠️

When user asks to add external URL content to ServiceNow KB:

STEP 1 - Fetch External Content:
1. Use SmartHttpPlugin.get_web_content(url="https://external-url.com") action
2. SmartHttpPlugin automatically:
   - Downloads HTML, JSON, or PDF content
   - Extracts clean text using BeautifulSoup
   - Removes ads, navigation, footers
   - Limits content to 75,000 characters
3. Verify content was extracted successfully
4. Extract title from content (usually first H1/H2 heading)

STEP 1b - Convert Extracted Content to HTML:
⚠️ CRITICAL: ServiceNow KB articles render HTML in the `text` field. Plain text will display as one unreadable wall of text.

Before creating the article, YOU MUST convert the extracted plain text into clean HTML:

**Conversion Rules:**
- Wrap ALL body text in `<p>` tags
- Convert lines that start with `- ` or `• ` into `<ul><li>` lists
- Convert numbered lines (1. 2. 3.) into `<ol><li>` lists
- Convert ALL‐CAPS lines or short lines followed by a colon into `<h2>` or `<h3>` headings
- Convert the page's main title into `<h1>` (used as short_description too)
- Preserve paragraph breaks as separate `<p>` blocks
- Bold any text that was bold/emphasized in the source
- Do NOT wrap the whole article in `<html>` or `<body>` tags — just the content elements

**Example transformation:**
Plain text:
```
Key features:
- Agentless vulnerability scanning
- Threat detection for servers
Plans include Defender CSPM, Servers, Containers.
```
HTML output:
```html
<h2>Key features</h2>
<ul>
  <li>Agentless vulnerability scanning</li>
  <li>Threat detection for servers</li>
</ul>
<p>Plans include Defender CSPM, Servers, Containers.</p>
```

⚠️ FULL CONTENT RULE: Use the COMPLETE extracted text from SmartHttpPlugin — do NOT summarize, paraphrase, or shorten it. The user wants the full source content in ServiceNow. If SmartHttpPlugin returned 5,000 words, put all 5,000 words (formatted as HTML) into the `text` field.

**CRITICAL - Publishing Knowledge Base Articles:**
⚠️ THE PORTAL PUBLISH BUTTON IS REQUIRED FOR ALL KNOWLEDGE BASES ⚠️

The ServiceNow workflow engine intercepts all `workflow_state` changes on the `kb_knowledge` table. A direct REST PATCH to `workflow_state="published"` is silently ignored — the API returns HTTP 200 but the article stays in draft. This applies to ALL knowledge bases.

The correct mechanism is the portal **Publish** button, which calls the internal workflow action. The difference between KBs is only the outcome:
- **IT knowledge base:** Publish button → Draft → Review (waits for approval before publishing)
- **All other KBs:** Publish button → Draft → Published immediately (no approval required)

⚠️ NEVER call updateKnowledgeArticle(workflow_state="published") to publish an article — it will not work.
