## Latest release notes

### **(v0.261.491)**

#### Bug Fixes

*   **Exports No Longer Start When the Prompt Forbids Them**
    *   A prompt that mentioned a format in order to rule it out, such as "JSON output is not permitted" or "Step 5D will generate the JSON", could still start a background export and replace the answer with a status message. Keywords now only suggest a file export or background run; a short model check confirms the user wants it before anything starts.
    *   "Do not create files", "do not initiate background processing" and "in chat only" are honored directly, each for its own action. "No files" does not block a background analysis, and neither affects memory or charts.
    *   If the check fails or is unsure, nothing is started and the reply says what was held back and how to ask for it. Background run submission and file publication also check the decision themselves.
    *   Adds the backend setting `request_intent_check_mode` (`active` by default, `shadow` to log only, `off`).
    *   (Ref: `functions_request_intent.py`, `functions_generated_file_exports.py`, `functions_tabular_orchestration.py`, `functions_tabular_generated_exports.py`, `route_backend_chats.py`, `functional_tests/test_request_intent_side_effect_gate.py`, `docs/explanation/fixes/TABULAR_EXPORT_NEGATED_REQUEST_FIX.md`, `docs/explanation/features/REQUEST_INTENT_CHECK.md`)

#### User Interface Enhancements

*   **Background Export Status and Answer in Chat Instead**
    *   The message shown when a background export or analysis starts now reads as an application status ("The app started a background job to generate the complete JSON for all 826 rows") instead of the assistant agreeing to do it.
    *   The background export card has an **Answer in chat instead** button that cancels the run and answers the same request in chat. Classic interface only.
    *   (Ref: `route_backend_chats.py`, `chat-messages.js`, `ui_tests/test_chat_background_generated_export_status.py`)

### **(v0.261.486)**

*   **Safer Error Responses and Fallback Logs**
    *   Deleting a personal model connection without governance access returns the same stable message as the other personal connection routes. Cache fallback warnings keep request-derived identifiers on one log line.
    *   (Ref: `route_backend_models.py`, `app_settings_cache.py`, `test_cosmos_wave1_cache_fallback.py`)
*   **Pull Request Checks and CodeQL Findings**
    *   The model catalog workflow lock includes the repository's coordinator agent, the Cosmos contract job has time for its full suite, and the offline test double supports the conditional updates used by stream replay without Redis.
    *   Branch CodeQL findings were resolved where they reflected real issues, including duplicate dictionary keys, dead code, unused imports, and unexplained exception handling.

*   **Custom Endpoint Credentials Use Only Their Configured Header**
    *   Custom and Microsoft MAI connections that send an API key in a named header, such as `api-key` or `Ocp-Apim-Subscription-Key`, no longer also send that key as an `Authorization: Bearer` token, which could forward gateway subscription keys to backend services.
    *   Custom Anthropic connections that use a bearer token send their `Authorization` header again. They previously sent no credential.
    *   (Ref: `functions_model_endpoint_auth.py`, `test_custom_model_endpoint_auth.py`, `test_custom_model_endpoint_foundation.py`, `test_microsoft_mai_model_connections.py`)

    *   (Ref: `functions_image_generation.py`, `test_ai_connection_image_runtime.py`, `test_image_generation_sdk_http.py`)

    *   A legacy group connection test resolves the active group once, so the saved-connection lookup and request validation always target the same group.
    *   (Ref: `route_backend_models.py`, `test_model_endpoint_secret_reference_hardening.py`)
*   **Routing Previews and Saves Keep the Runtime Path Order**
    *   A routing preview for a connection without a stored path order now shows the same request URL the saved connection calls (model path first), instead of assuming connection path first.
    *   Saving an existing explicit-routing connection without a stored path order in the classic admin page no longer switches it to connection path first. New connections still start with connection path first.
    *   (Ref: `route_backend_models.py`, `admin_model_endpoints.js`, `test_model_endpoint_scope_gate_enforcement.py`)
*   **Chat Table Formatting No Longer Stalls on Crafted Responses**
    *   Unwrapping markdown tables from code blocks no longer backtracks exponentially, so a response with a few dozen pipe-only lines cannot freeze the chat tab. The same blocks are unwrapped as before.
    *   (Ref: `chat-messages.js`, `test_classic_js_codeql_xss_redos_fixes.py`)
*   **Classic Pages Render Untrusted Text as Text**
    *   Read-aloud strips markup with an inert parser, export conversation IDs are escaped in attributes, inline export button labels are plain text, and Control Center toasts never interpret HTML.
    *   The Control Center and workspace user searches no longer place search terms or directory names into markup or inline script.
    *   (Ref: `chat-tts.js`, `chat-export.js`, `chat-messages.js`, `control-center.js`, `control_center.html`, `workspace-manager.js`, `test_classic_js_codeql_xss_redos_fixes.py`, `test_stored_xss_admin_rendering_fix.py`)

### **(v0.261.475)**

#### Bug Fixes

*   **Missing Cosmos Containers Are Created Under Managed Identity**
    *   With managed identity, Cosmos DB refuses to create containers through its data-plane endpoint, so a release that added a container failed to start after `azd deploy` unless `azd provision` had created it first. When that refusal happens, the app now creates the missing container through Azure Resource Manager with the same partition key, TTL and indexing policy, using the Contributor role the deployers already give its identity.
    *   The app finds the Cosmos account's subscription and resource group from `AZURE_SUBSCRIPTION_ID` and `AZURE_RESOURCE_GROUP`, which the Terraform and Azure CLI deployers now set as Bicep already did. When they are absent, as on an older deployment updated only with `azd deploy`, it uses its own App Service subscription and resource group, so nobody has to supply them.
    *   The Bicep and Terraform deployers now declare all 75 containers the app uses. Bicep was missing 11 (`conversation_handoffs`, `support_exports`, `orchestration_runs`, `orchestration_run_steps`, `document_access_index`, `content_screening`, `key_vault_secret_reminders`, `bitbucket_connections`, `action_credential_state`, `m365_connections`, `m365_execution_runs`), and Terraform was also missing `custom_pages`, `governance_policies` and `governance_item_policies` (deployers version 1.0.41).
    *   New `deployers/Grant-CosmosContainerCreatePermission.ps1` lets an admin grant the identity a narrow custom role (container read and write only) for deployments where it does not have Contributor on the Cosmos account. It supports `-WhatIf` and `-UseBuiltInRole`.
    *   (Ref: `functions_cosmos_container_provisioning.py`, `config.py`, `cosmosDb.bicep`, `main.json`, `terraform/main.tf`, `deploy-simplechat.ps1`, `Grant-CosmosContainerCreatePermission.ps1`, `test_cosmos_container_arm_provisioning.py`, `COSMOS_CONTAINER_CREATION_MANAGED_IDENTITY_FIX.md`)

#### Bug Fixes

*   **Whole-Workspace Chat Links and Reasoning**
    *   Workspace chat links can now bind one whole personal, group, or public workspace in addition to explicit document selections.

The workflow refuses an environment that configures both a vault key and a secret, and checks that the secret matches the bundled public key before signing.
    *   (Ref: `model_catalog_package.py`, `model_catalog_updates.py`, `scripts/publish_model_catalog.py`, `.github/workflows/publish-model-catalog.yml`, `model_catalog_trusted_keys.json`, `model_catalog_development_trusted_keys.json`, `admin_settings_fields.py`, `ModelCatalogUpdates.tsx`, `model_catalog_updates.js`, `MODEL_CATALOG_PUBLISHER_KEY_SETUP_FIX.md`, [#1967](https://github.com/microsoft/simplechat/pull/1967))
